# CM311-1 刷机操作手册：TTL + SSH 方案

**目标设备**：魔百盒 CM311-1（YST / S905L3 系 / 2+16G / 无 WiFi / 12V 1A）
**方案**：TTL 串口为主控通道 + SSH 为日常远控

> 下文包路径均为示意，请按你自己的存放位置替换。

---

## 0. 为什么是 TTL

来自社区实测（八米云 U 盘启动教程）：

> S905L / S905L2 / S905L3A **支持显示器显示**，可以看到显示器的跑码信息；
> **S905L3 / L3B 不支持显示器显示，需要接入 TTL。**

本机是 **S905L3 系** → **TTL 是唯一的可视化通道**。
屏幕上看不到任何东西，串口日志就是你的"显示器"。

## 2. 阶段一：TTL 验机（到货第一件事）

### 2.1 接线

```
USB-TTL 转接板          盒子 TTL 焊盘
   GND      ───────────  GND      ← 必须先接，且只需这一根判断线序
   RX       ───────────  TX       ← 交叉！
   TX       ───────────  RX       ← 交叉！
   VCC      ───────────  ✗ 不接    ← 盒子自己供电，绝对不接
```

**要点**

- 转接板跳线设 **3.3V**（Amlogic UART 是 3.3V 逻辑）
- **RX/TX 必须交叉**：转接板的 RX 接盒子的 TX
- **VCC 不接**（盒子由自己的 12V 电源供电）
- 先用万用表/通断档确认盒子上哪个焊盘是 **GND**，别信线序颜色

### 2.2 串口参数

| 参数 | 值 |
|---|---|
| 波特率 | **115200** |
| 数据位 | 8 |
| 校验 | None |
| 停止位 | 1 |
| 流控 | None |

Windows 串口工具可选：PuTTY（Serial）、MobaXterm、SecureCRT、Tera Term。
确认设备管理器里能看到 COM 端口号。

### 2.3 上电时序（关键）

```
① 串口工具先打开、连上 COM 口     ← 必须先开，否则错过启动日志
② 接好 TTL 三根线（盒子不通电）
③ 给盒子插 12V 电源
④ 立刻观察串口输出
```

**注意**：如果第一次没抓到，断电、保持串口打开、再上电。

### 2.4 日志里要抓什么

**目标一：确认平台家族**

在 u-boot 输出里找：

| 关键字 | 结论 |
|---|---|
| **`gxl`** | S905L3 / L3B → **本方案路线** ✅ |
| **`g12a`** | S905L3A → 型号货不对板，需重新评估 |

**目标二：区分 L3 还是 L3B**（决定用哪个镜像）

| 线索 | 对应 |
|---|---|
| u-boot 报 `s905l3` / dtb 名含 `s905l2-x7-5g` | → `s905l3` 镜像（机型库 ID 122） |
| u-boot 报 `s905l3b` / dtb 名含 `s905l3b-m302a` | → `s905l3b` 镜像（机型库 ID 127） |
| 实在分不清 | 先试 `s905l3`，不行换 `s905l3b`，最后试 `s905l3-cm211` |

**目标三：拦住自动启动**

开机时在串口里**狂按回车/空格**，打断 u-boot 自动启动，进入 `u-boot>` 提示符。
（这一步让你有机会手动控制从哪个设备启动）

### 2.5 记录

把完整日志存到 `E:\CM311-1\notes\ttl-boot-log.txt`，
并在 `notes\README.txt` 里记下：平台 = gxl / 芯片 = L3 或 L3B。

### 2.6 附加验证（不用拆机）

在 u-boot 提示符下可确认引导环境：

```
printenv
```

看 `bootcmd`、`bootargs` 里的平台标识。**这是厂商无法伪造的层。**

## 3. 阶段二：写盘与启动

### 3.1 选启动介质

**本机结论：用 U 盘当启动盘。** 理由见 [`硬件兼容性记录.md`](硬件兼容性记录.md)。

| 方案 | 本机可行性 | 说明 |
|---|---|---|
| **U 盘** | ✅ **推荐** | 16GB 正牌，兼容性最好 |
| SSD + thinkplus K01-A 硬盘盒 | ❌ **不建议** | 该盒为 **JMS578** 主控，UAS 兼容性差，且 quirk 参数在启动阶段无效 |
| 老 HDD（实验品） | ⚠️ 仅试错 | 机械盘启动电流大，u-boot 识别难度更高 |

> **为什么硬盘盒不能当启动盘**：`usb-storage.quirks` 是 **Linux 内核参数**，
> 而启动阶段是 **u-boot** 在工作，它没有内核模块机制，用不上这个参数。
> 详见 [`硬件兼容性记录.md`](硬件兼容性记录.md) 第二节。

**⚠️ 启动介质上的原有数据会被完全覆盖**，先备份。

### 3.2 写盘

1. 运行 `tools\balenaEtcher-2.1.7.Setup.exe` 安装
2. 选对应镜像（见 2.4 的结论）
3. 写入 U 盘
4. **建议准备两样可替换的介质**——社区反复提醒「一个 U 盘不行就换一个，这可能是兼容性问题」

### 3.3 ⚠️ 启动阶段：不要经过 Hub

**这是本方案最容易翻车的一点。**

| 接法 | 供电 | u-boot 识别 | 结论 |
|---|---|---|---|
| **直插盒子（靠近网口的口）** | ⚠️ 可能不足 | ✅ 最好 | **首选** |
| **经过供电拓展坞** | ✅ 充裕 | ❌ 较差 | 备选 |

**两难**：供电与识别率在这里是矛盾的——拓展坞解决供电，却增加一层 USB 枚举，
而老旧 u-boot 对 Hub 后面的设备识别率明显下降。

**处理顺序（照这个顺序试）**

```
① 直插盒子 USB 口（靠近网口那个），不经过拓展坞
   启动成功 → 就用这个接法，不要画蛇添足
② 直插失败 / 启动中掉盘
   → 再套供电拓展坞试
③ 拓展坞也认不到
   → 这台 u-boot 不吃 Hub，换另一种介质（U 盘）
```

**⚠️ 为什么这里要格外小心**：本机是 **L3，无显示输出**。
启动卡在哪一步**屏幕上完全看不到**，只能靠 TTL 串口判断。
所以启动阶段**每增加一个变量（Hub、第二个设备），排查难度就翻一倍**。

### 3.4 ⚠️ 一次只插一个存储设备

**写 eMMC 期间，盒子上只能有一个存储设备。**

- ❌ 不要同时插 SSD 和 U 盘
- ❌ 不要插第二个 U 盘
- ❌ 不要经过 Hub 连着别的东西

**原因**：设备多了容易认错设备节点，写错就会覆盖掉你正在运行的系统。

### 3.5 触发启动（两条路，先试 ADB）

**路线 A：ADB 触发（省事，但看不见）**

```powershell
cd E:\CM311-1\tools\platform-tools
.\adb.exe connect <盒子IP>:5555
.\adb.exe devices              # 确认连上
```

然后可用 bat 脚本 / 开心电视助手 / `adb shell reboot update`
让盒子从启动介质启动。

> ⚠️ 若盒子**没有**在 5555 端口监听，需要先用双公头 USB 线连接电脑，执行
> `adb tcpip 5555` 切到网络模式，再 `adb connect <IP>:5555`。
> **所以双公头线不是废的**——在"启用网络 ADB"这一步可能用得上。

⚠️ **L3 无显示输出**：触发后屏幕是黑的，**必须同时用 TTL 串口观察**有没有真的进启动模式。

**路线 B：TTL 直接引导（可控，推荐配合使用）**

在 u-boot 提示符下：

```
run usb_boot
```

（若该变量不存在，用 `printenv` 查看本机定义的实际 USB 启动变量名，
或从 u-boot 的启动菜单里选择 USB 启动项）

⚠️ **启动介质要插在靠近网口的那个 USB 口**，且**优先不经过 Hub**（见 3.3）。

## 4. 阶段三：装到 eMMC

### 4.1 首次进入系统

启动介质启动成功后：

- 默认用户名 **root**，默认密码 **1234**（首次登录会强制改密码）
- 设完密码会提示创建普通用户，可跳过

### 4.2 ⚠️ 第一件事：备份 eMMC

```bash
armbian-ddbr
```

按提示备份，产物在 `/ddbr/backup.img`。
**L3 的安卓底包比 L3A 难找，这个备份是救命符。** 建议拷到电脑保存。

### 4.3 安装到 eMMC

```bash
armbian-install
```

按菜单选择本机对应板型（`s905l3` / `s905l3b`）。

**⚠️ 不要用网文里的硬编码 dd 命令**（如 `dd if=armbian.img of=/dev/mmcblk1`）——
分区不会自动扩容，且设备节点编号不保证一致，写错会覆盖正在运行的系统。
**用 `armbian-install`，它内部会处理 dtb、u-boot、分区扩容。**

### 4.4 收尾

1. 安装完成 → **断电**
2. **拔掉启动介质**（U 盘）
3. 重新上电 → 应从 eMMC 启动 Armbian

**⚠️ 写 eMMC 期间盒子上只能有那一个启动介质**（见 3.4）：
不要同时插 SSD 和 U 盘，不要经过拓展坞连着别的东西。

### 4.5 挂载数据盘（SSD + thinkplus K01-A）

**本机启动介质是 U 盘，所以这个硬盘盒从头到尾都是当数据盘用**，
不需要"从启动盘转数据盘"那一步。

**⚠️ 但必须先打 UAS quirk，否则会出现掉盘/卡死/几 KB/s 的症状。**

```bash
# 1. 编辑启动参数
sudo nano /boot/uEnv.txt

# 2. 在 extraargs 行末尾追加（注意是 0x152d:0xa578，本机 K01-A 的 ID）
extraargs=... usb-storage.quirks=0x152d:0xa578:u

# 3. 重启
sudo reboot

# 4. 验证：插上硬盘盒后查看驱动
lsusb -t
```

**成功标志**：`Driver=usb-storage`（而不是 `Driver=uas`）

> **⚠️ 别照抄网上的 ID**：恩山原帖用的是 `152d:0576`，某 H1 硬盘盒是 `152d:8888`，
> **本机 K01-A 是 `152d:a578`**，抄错了 quirk 不生效。
>
> **⚠️ 别顺手加 `console=ttyAML0,...`**：原帖明确警告，不同固件控制台端口定义不同，
> 强行指定**极易黑屏无法启动**。

**接法**：装回硬盘盒 → **经供电拓展坞**接盒子 → 挂载使用。

> 有用户反馈禁用 UAS 后速度只有 2MB/s，**加独立供电后改善** —— 供电是独立因素。
> 所以拓展坞在这里仍有价值。

详见 [`硬件兼容性记录.md`](硬件兼容性记录.md) 第二节。

## 5. 阶段四：SSH 远控

### 5.1 首次 SSH

1. 盒子接网线（**无 WiFi，只能有线**）
2. 路由器后台找设备名 **`armbian`** 的 IP
3. 电脑（同局域网）SSH：

```powershell
ssh root@<新IP>
```

### 5.2 ⚠️ 安全必修（默认配置不能就这么放着）

| 项目 | 动作 |
|---|---|
| root 密码 | 首次登录已强制改 → 确认改成了强密码 |
| 是否允许 root 直接登录 | 建议关闭 `PermitRootLogin`，改用普通用户 + `sudo` |
| **SSH 密钥登录** | 强烈建议配置，之后禁用密码登录 |
| SSH 端口 | 可改为非 22（降低扫描噪音，非必需） |
| 是否暴露到公网 | **默认不要**。要外网访问用 VPN / 内网穿透，别直接端口映射 |

### 5.3 日常运维

- TTL 保持接着（或至少随时能接上）→ **保底通道**
- SSH 为主力
- 网络断了 / 起不来 / 配错防火墙 → **TTL 依然能进**

**这正是"TTL + SSH"组合的价值：SSH 方便，TTL 保命。**

## 6. 故障排查对照表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 串口无任何输出 | 接线错（TX/RX 没交叉）/ 波特率错 / GND 不对 | 逐项复核 2.1、2.2 |
| 串口是乱码 | 波特率不对 | 确认 115200 |
| ADB 连不上 `5555` | 安卓未开 ADB | 安卓设置里开 USB 调试；或改走 TTL |
| 触发后黑屏无反应 | **L3 正常现象**（无显示输出） | 看 TTL 日志判断 |
| u-boot 无 `usb_boot` 变量 | 变量名不同 | `printenv` 查实际名称 |
| 卡在开机 logo | **dtb 选错** | 换另一个镜像（l3b / cm211）重试 |
| U 盘 / SSD 不被识别 | 介质兼容性 / 经过了 Hub / 插错 USB 口 | 换直插靠近网口的口；去掉 Hub；换另一种介质 |
| 文件属主变成 `1023` | 在安卓下插着 U 盘再从 U 盘引导 | 重写 U 盘，冷启动引导 |
| 完全起不来 | bootloader 问题 | USB Burning Tool 线刷（Burning Tool + 双公头线） |

## 7. 红线（不可逆风险）

| 风险 | 后果 | 防范 |
|---|---|---|
| **12V 电源极性插反** | 烧 PMIC/SoC，**永久报废** | 万用表量原装头 → 量新头 → 一致才插 |
| **TTL 的 VCC 接上** | 可能损坏 UART | VCC 一律不接 |
| **TTL 跳线设成 5V** | 可能损坏 SoC UART | 确认 3.3V |
| **短接 eMMC 引脚失手** | 熔锡焊死，eMMC 报废 | 用免拆神器替代镊子 |
| 写错 eMMC 设备节点 | 覆盖系统 | 用 `armbian-install`，别手敲 dd |

**软件层面基本刷不死**：Amlogic 的 BootROM 烧在 SoC 硅片里，物理不可擦除，
最坏情况可用 USB Burning Tool 线刷救回。
**真正不可逆的只有电源极性和手工短接。**
