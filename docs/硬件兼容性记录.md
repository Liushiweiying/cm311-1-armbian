## 二、⚠️ 联想 thinkplus K01-A 的 JMS578 兼容性问题

### 实测识别结果

```
USB Attached SCSI (UAS) 大容量存储设备
  VID_152D  PID_A578
```

| 项目 | 值 |
|---|---|
| 主控 | **JMicron JMS578** |
| **设备 ID** | **`152d:a578`** ← 本机专用，务必记牢 |
| 电脑上工作模式 | UAS |

### 问题：UAS 驱动与 Linux 兼容性差

**症状**（[恩山原帖](https://www.right.com.cn/forum/forum.php?mod=viewthread&tid=8466097)）：

- 🐢 读写速度极慢，**甚至只有几 KB/s**
- 🔌 频繁断连，硬盘莫名其妙消失
- 💥 大文件传输时**系统卡死**

**根因**：

> 硬盘盒主控芯片（尤其是常见的 **JMicron JMS578/JMS580**、Realtek 等系列）与 Linux
> 内核默认的 **UAS (USB Attached SCSI) 驱动存在兼容性冲突**。
> **N1 的 USB 2.0 控制器对 UAS 支持不佳。**

本机盒子也是 **USB 2.0**，属于同一类问题。

### ❌ 别照抄网上的 ID

| 来源 | 用的 ID |
|---|---|
| 恩山帖主 | `152d:0576` |
| 某 H1 硬盘盒 | `152d:8888` |
| **本机 K01-A** | **`152d:a578`** |

**ID 不同，抄错了 quirk 不生效。** 原帖里就有人因此"还是有 uas"。

### ✅ 解决方案：禁用 UAS，回退到 BOT

**关键**：必须加在 **`extraargs=`** 行，不是随便加一行。
原帖多人踩坑："以为只是添加 `usb-storage.quirks=...` 就行了，重启几次都不行"。

```bash
# 1. 编辑启动配置（内核不同文件名可能不同）
sudo nano /boot/uEnv.txt

# 2. 在 extraargs 行末尾追加（u = 强制用 usb-storage/BOT 协议）
extraargs=... usb-storage.quirks=0x152d:0xa578:u

# 3. 重启
sudo reboot

# 4. 验证
lsusb -t
```

**成功标志**：

```
Driver=uas            ← ❌ 未生效
Driver=usb-storage    ← ✅ 修复成功
```

**⚠️ 避坑**：原帖明确提醒**不要**顺手加 `console=ttyAML0,...`：

> 强烈建议不要这样做！不同固件版本对控制台端口定义不同，**强行指定极易导致黑屏无法启动**

### ⚠️ 两个已知副作用

1. 有用户反馈禁用 UAS 后**速度只有 2MB/s**，**加独立供电后改善** ← 供电是独立因素
2. 修改 `/boot` 有风险，参数写错可能起不来 → **务必先确认 TTL 通路可用**

### 🎯 结论：K01-A 只当数据盘，不当启动盘

| 用途 | 是否可行 | 说明 |
|---|---|---|
| **数据盘**（系统起来后插） | ✅ 可行 | 打 UAS quirk 后稳定 |
| **启动盘** | ❌ **不建议** | 见下 |

**为什么不能当启动盘**：`usb-storage.quirks` 是 **Linux 内核参数**，
而**启动阶段是 u-boot 在工作，它没有内核模块机制，用不上这个参数**。

u-boot 认不认 JMS578 取决于它的编译选项，不确定性高。

**若将来确实要用 SSD 启动**：换 **ASM1153E 主控**的盒子（`VID_174C`）——
恩山原帖称其"完美识别"。

## 三、亿贝联 YBL340G-A（CH340）TTL 模块

### 这是"真·可切 3.3V"的模块

官方文档《YBL340G-A 标准版、增强版串口模块使用说明》第 2 节原文：

> 根据使用环境配置模块的工作电压，分 **5V 与 3.3V 两种电压模式**……
> **确保两者通信电平一致**，否则可能出现通信失败的情况。

切的是**工作电压**，不只是 VCC 输出 —— 这一点比廉价 CH340 板子好。

### 跳线配置（标准版和增强版不同！）

| 版本 | 配 5V | 配 **3.3V**（本机需要） |
|---|---|---|
| **标准版** | 红色帽：`VIN` ↔ `5V` | 红色帽：**`VIN` ↔ `3.3V`** |
| **增强版** | 红色帽：`V1` ↔ `5V` | 红色帽：**`V1` ↔ `3.3V`**<br>黄色帽：**`V2` ↔ `3.3V`** |

**⚠️ 配错不会烧板子，但会通信失败。**

### 三个硬性注意

1. **短路帽配好后不能拔** —— 拔了模块不工作，电脑发现不了串口
2. **接外部设备只需三根线** —— `RXD` / `TXD` / `GND`，**电源脚不接**（盒子自己供电）
3. **必须交叉** —— 模块 `RXD` → 盒子 `TXD`，模块 `TXD` → 盒子 `RXD`

### 自环测试（不用盒子，现在就能做）

```
① 标准版：杜邦线短接 RX-TX   增强版：黄色帽短接 RX-TX
② 插电脑 USB，红灯亮
③ 打开资料里的 COMTransmit.EXE
④ 发送 112233 → 接收区收到 112233 = 模块正常
```

资料已解压归档于 `notes\YBL340-资料\`（含驱动、CH340 数据手册、COMTransmit、putty）。

## 五、启动介质分工（据上述硬件确定）

```
U 盘 (16GB)          →  ✅ 启动盘（写 Armbian 镜像，引导盒子）
盒子本体 eMMC (16GB)  →  ✅ 系统盘（armbian-install 写入，最终跑系统）
SSD + K01-A 硬盘盒    →  ✅ 数据盘（系统起来后再插，须打 UAS quirk）
```

**⚠️ 启动阶段一次只插一个存储设备。**
**⚠️ 写入 eMMC 时，硬盘盒不要插。**

理由：JMS578 在启动阶段不可靠；且多设备并存容易认错设备节点，写错会覆盖正在运行的系统。
